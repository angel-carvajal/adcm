# adcm-toolkits

Public ADCM toolkits: the Council multi-advisor deliberation framework (generic, bring-your-own-context), a code-project context generator that builds a lazy-loading, refreshable knowledge base of a codebase (architecture, API surface, data models, config, security, conventions), a business context generator that interviews the owner and researches the business website to produce an installable, lazy-loading business-context skill (identity, offering, market, brand voice, sales, operations, objectives, plus a confidential internal file), and an execution-prompt architect that turns goals + deep code analysis into a six-document execution plan (executive proposal, master plan, detailed plan, timeframe plan with critical path and week-by-week schedule, task tracker, execution protocol) with self-contained copy-paste prompts per wave (each embeds a SCOPE manifest: files to modify with why, impact census of shared-surface consumers, freshness checks — clean sessions execute without re-analyzing the project) and an optional single-file HTML with a CSS Gantt timeline. The context generator also emits a usage-map (shared surfaces → consumer census) and supports delta refreshes (--update) at wave close. Use for structured multi-perspective decisions, to document a codebase or a business, or to plan and prompt large tasks and migrations. It also ships a deterministic status digest: at session start the main session reads a ≤40-line summary of task.md — waves, last logbook entry, pending human actions, artifact state — generated by script, with a Sonnet fallback only when the tracker does not parse. It also ships six role agents — courier, auditor (Opus, no Edit/Write), executor, executor-frontend (the frontend-design skill preloaded), researcher and digester — so the default model and the tool set of every role delegation are fixed by the plugin instead of by the brief. It also ships a renovate flow that upgrades an existing brain to the current protocol from one phrase: a deterministic check copies the missing scripts and lists the missing blocks, one executor per block applies them, nothing is re-planned. It also flags obsolete protocol notes in the project's memory and CLAUDE.md: memory notes get a dated correction appended, CLAUDE.md lines are corrected in place, nothing is deleted. Since 0.15.0 the plan-page generators survive an inline `<!--`, digit-less and lowercase-suffix wave ids and multiple deliveries per wave, prompts.html keeps closed waves as summaries so it stays under the re-issue size, the courier respects per-account URLs, and the agent budget is 20 per session. Since 0.17.0 the explainer-video skill records web-app explainer videos with AI voice-over from approved storyboards, by script, with zero model turns. Since 0.18.0 the design-direction-architect skill builds one fixed design board by script, with five tabs, three live options and a selftest. Since 0.20.0 the launchers live in `scripts/launchers/` (a top-level `bin` folder is refused by claude.ai and Cowork) and a plugin SessionStart hook puts them on the Bash PATH. Since 0.21.0 a plugin Stop hook asks the main session to send one phone notification (the native `PushNotification` tool) when a turn ran longer than five minutes, and the delivery-close, stop and gate steps tell the main session to notify the owner once, never from a sub-agent. Since 0.19.0 the context generator also writes a lazy brain map and a dependencies.md, the dependency-renovate skill ships one verified patch-and-minor MR plus one MR per major from a deterministic plan, the delivery close can add a tailnet preview link that opens the local preview from a phone on any network, and both executors apply the plan's reuse verdict through the map. Since 0.22.0 a main-thread guard keeps the main session orchestrating (hooks), work runs in one clean session per phase with handoffs, doc-sync is a two-phase script-checked edit, and a plan-audit gate precedes prompt rendering.  ·  v0.22.1

## Skills

- **`artifact-courier`** — Hands the delivery close of a session to the `adcm-toolkits:courier` agent (Sonnet, one per batch): runs the plan-page generators, regenerates and republishes the stale claude.ai Artifacts registered in `artifacts.json` (in place, or re-issued as a new artifact above ~600 KB), stamps `published_at`/`version`/`sha256` so the `artifact-guard` Stop hook trusts it, returns the visual-check media paths (the main session sends them) and the links block to paste verbatim.  ·  invoke: `/adcm-toolkits:artifact-courier`
- **`agentic-seo-report`** — Audits a live website for how well search engines AND AI agents can find, read and use it: combines the free is-agentic.com agent-readiness score with local checks (llms.txt, hreflang reciprocity, JSON-LD validity, schema coverage, sitemap health, AI-crawler posture, text visible without JS), writing findings ranked by traffic impact, each with the command that reproduces it — and it honors per-project confidentiality rules so it never recommends publishing internal pricing or process detail.  ·  invoke: `/adcm-toolkits:agentic-seo-report`
- **`business-context-generator`** — Interviews a business owner and researches the business website to generate an installable, lazy-loading business-context skill of the form `business-init-[business-slug]`. Now also mines EXISTING sources first — sales decks, database migrations and price catalogs, quoting tools, a sibling venture's execution docs, brand tokens and memory files — one sub-agent per source family under the 20-agent tiered protocol, consolidating a fact sheet where every fact carries its source path, date, confidence and confidentiality class, then interviews only for the UNKNOWNs.  ·  invoke: `/adcm-toolkits:business-context-generator`
- **`code-project-context-generator`** — Scans a code project, builds a structured map of its architecture, and generates an installable skill of the form `code-project-context-[project-name]` with lazy-loading (the resulting SKILL.md loads…  ·  invoke: `/adcm-toolkits:code-project-context-generator`
- **`council`** — Convenes a council of 5 advisors (Strategist, Adversary, Outsider, Operator, Futurist) plus a Chairman to deliberate on a decision and deliver an actionable verdict.  ·  invoke: `/adcm-toolkits:council`
- **`dependency-renovate`** — Renews the dependencies of one project on demand: a deterministic `deps-check` plans the run (outdated packages, advisories, Node LTS status, policy holds), one Sonnet executor ships one verified MR with every patch and minor bump and a before/after visual smoke (`deps-smoke`), one Opus executor per major ships its own stacked Draft MR with migration notes, an Opus auditor gates, and Claude never merges. Also keeps the project's `dependencies.md` current.  ·  invoke: `/adcm-toolkits:dependency-renovate`
- **`design-direction-architect`** — Researches and locks a web design direction before any code is written: interviews the owner, mines the Framer template marketplace, Awwwards, 21st.dev (magic MCP), Pexels and a manual inspiration folder, triages 15+ candidates and presents 5 finalists backed by two or more sources. Scripts build one fixed design board (5 tabs) where the owner drops references, compares exactly 3 options and exports tokens; the board writes a reusable pack to `.design/` (brief, references, tokens, commerce, assets, decisions) that the building skills consume; it never builds the site itself.  ·  invoke: `/adcm-toolkits:design-direction-architect`
- **`execution-prompt-architect`** — Turns a task description plus deep code analysis into a complete execution-plan family: an executive proposal (what is sought and what to approve, for stakeholders), a master plan (strategy and decisi…  ·  invoke: `/adcm-toolkits:execution-prompt-architect`
- **`explainer-video`** — Records explainer videos of a local web app with an AI voice-over, on-screen captions and subtitles. A deterministic script (the `explainer-record` launcher) opens the browser, performs each storyboard step, speaks it and muxes mp4 + srt + poster + contact sheet, so the model only writes storyboards and audits the result, never records. Two phases: one executor writes the storyboards, the owner approves them, then the script records with zero agents. Local apps only (`allowHosts` defaults to localhost) and secrets only as `{{env:VAR}}`, redacted in every output.  ·  invoke: `/adcm-toolkits:explainer-video`

## Requirements

- `artifact-courier`: Python 3 (stdlib) for `scripts/courier_preflight.py`; a session with the Agent tool whose sub-agents expose the Artifact tool; the Chrome extension for screenshots/GIFs (sub-agents can use it) and SendUserFile in the main session to deliver them (sub-agents do not have it); optional: the Tailscale Standalone app with MagicDNS and HTTPS certificates for the phone-on-any-network preview link (`tailnet-preview doctor`).
- `scripts/launchers/` launchers (`courier-preflight`, `status-digest`, `renovate-check`, `plans-regen`, `prompts-regen`, `explainer-record`, `design-board`, `tailnet-preview`, `map-refresh`, `deps-check`, `deps-smoke`, `check-memory-index`, `plan-audit`, `docsync-apply`; reach the Bash PATH through the plugin's SessionStart hook, `hooks/hooks.json` → `scripts/launchers-path.sh`; executable bit required). In auto permission mode the classifier may deny the courier's registry seal (`courier-preflight … --mark-published`, a local edit of the project's `artifacts.json`) as "Create Public Surface"; the documented remedy is an `autoMode.allow` prose exception in your user settings (keep `"$defaults"` first) describing that seal as a local file edit — see `scripts/launchers/README.md`. If a seal is still denied, the courier returns `REGISTRY: blocked by permissions: <command>` and you run it with `!`.
- Plugin Stop hook (ships in `hooks/hooks.json`, no registration, Python 3 stdlib): `scripts/notify-stop.py` — after a turn longer than `ADCM_NOTIFY_MIN_SECONDS` (default 300) it asks the main session to call the native `PushNotification` tool once with a fixed text (`Claude finished in <folder>` / `Claude needs you in <folder>`); when the final message ends with the links block it only emits a desktop notification, so the links stay last. Silent with `ADCM_NOTIFY=off`, while background tasks or scheduled wake-ups are pending, on a re-entrant stop, in headless (`-p` / SDK) runs and on Bedrock/Vertex/Foundry; no state file, no external service. Phone delivery needs Remote Control connected and the `/config` toggle "Push when Claude decides"; the tool skips itself when you are at the terminal.
- Hooks (owner-installed, Python 3 stdlib): `artifact-guard.py` (Stop; demands the courier's links block, once per delivery close) and `merge-guard.py` (PreToolUse · matcher `Bash|mcp__.*merge.*` · timeout 10; Claude never merges an MR/PR — CLI, API, MCP tools, `git merge`/`rebase`/`reset` onto a protected branch and auto-merge push options), both in `skills/execution-prompt-architect/templates/`. Copy them to `$CLAUDE_CONFIG_DIR/hooks/` (default `~/.claude/hooks/`) and register them in the user `settings.json`; `renovate-check` prints `review:` lines when they are missing or outdated — see `scripts/launchers/README.md`.
- `agentic-seo-report`: No runtime dependencies. Reads the free is-agentic.com public API plus local checks against the project's own site content; honors an optional project-rules file for confidentiality.
- `business-context-generator`: No runtime dependencies. Markdown-only skill. Uses AskUserQuestion for the interview and WebFetch for website research when available; the mining mode fans out one sub-agent per source family (Claude Code); degrades to a plain-text interview without sub-agents. Works in Claude Code, Cowork, and claude.ai.
- `code-project-context-generator`: Python 3 (stdlib only) for the scanner and `map-refresh`.
- `council`: No runtime dependencies. Markdown-only skill read by Claude. In Claude Code, parallel advisor execution uses the built-in Task tool; in claude.ai/Cowork it falls back to sequential context-isolated reads. Works in Claude Code, Cowork, and claude.ai.
- `dependency-renovate`: Python 3 (stdlib) for `deps-check`; Node >= 20 + playwright-core >= 1.61 + Chrome for `deps-smoke` (`deps-smoke doctor`); network access to the package registries (read-only) and the project's own package manager; a project with a `code-project-context-*` skill for the `dependencies.md` update.
- `design-direction-architect`: Python 3 (board builder) · Node >= 20 + playwright-core >= 1.61 + Chrome (captures; `design-board doctor`) · WebSearch for market and Awwwards · Pexels reads `PEXELS_API_KEY` · 21st.dev needs the `magic` MCP · Pinterest is a manual folder.
- `execution-prompt-architect`: Works with any Claude model. In Claude Code the code analysis fans out to sub-agents using the model/effort the user picks; in environments without sub-agents it degrades to sequential analysis. Sub-agent fan-out is budgeted at 20 per session (a planning run, each clean wave session and a renovation count separately) with fixed roles by model tier: the main session (Fable) orchestrates and runs the DoD, Opus sub-agents investigate and audit (and implement ⚠gate waves), Sonnet sub-agents implement from executor briefs, with an escalation ladder Sonnet → Opus → Fable — in every effort level, ultracode included. Generated prompts are tuned for Fable at high effort but run on any model.
- `explainer-video`: Node >= 20 (the `explainer-record` launcher picks the newest nvm 2x install, else the `node` on PATH), `ffmpeg` and `ffprobe`, `playwright-core` >= 1.61 (project `node_modules`, `PW_CORE_DIR` or the npx cache) with Chrome or Chromium, and one TTS engine chosen with `REC_TTS`: `edge-tts` (default, needs network), `piper` (offline) or macOS `say`; the voice home is `REC_TTS_HOME` (default `~/.local/share/adcm-voz`, recipe in `skills/explainer-video/templates/voice-install.md`). `explainer-record --doctor` checks all of it. A sample app for smoke recordings lives in `skills/explainer-video/fixtures/demo/`.
- `executor-frontend` (agent): preloads the official `frontend-design` plugin skill (install the official `frontend-design` plugin); `impeccable` and other design skills are loaded per brief.

## Hooks

Shipped in `hooks/hooks.json` (no registration, Python 3 stdlib, all fail open):

| Hook | Events | What it does |
|---|---|---|
| `scripts/main-thread-guard.py` | SessionStart, UserPromptSubmit, PreCompact, PreToolUse, PostToolUse | Keeps the main session orchestrating; rules below |
| `scripts/notify-stop.py` | Stop | One phone notification after a long turn |
| `scripts/launchers-path.sh` | SessionStart | Puts `scripts/launchers/` on the Bash PATH |

Stays owner-installed (copied to `$CLAUDE_CONFIG_DIR/hooks/` and registered in the user `settings.json`, see `scripts/launchers/README.md`): `artifact-guard.py` (Stop) and `merge-guard.py` (PreToolUse).

### main-thread-guard rules

Main session only (sub-agents pass after T0); first match wins; unattended runs (`-p`, SDK) are never denied except by T0.

| Id | Denies |
|---|---|
| T0 | any change to the guard's state folder or its own files, from any thread: there only plain one-line read-only commands pass (no heredoc, substitution, comment, unbalanced quote, write redirection or env prefix); editors denied; scheduling tools with an escape phrase refused |
| R1 / R1b | 3rd compaction: every tool except the handoff and memory files; 2nd compaction: every other tool is denied until a handoff of at least 300 characters is written (state, pending items, live agents, next step, resume prompt) |
| M1 | a memory index (`MEMORY.md`) line longer than 150 characters |
| R6 | a 4th tool call in a status turn; a status question is a prompt that is essentially the status phrase alone ("where did we leave off"), not an ordinary prompt that merely contains the word |
| R3 | whole-file reads of files over 40 KB or of plan docs, image and PDF reads, transcript dumps |
| X1 | browser tools and Artifact publish or read |
| X2 | edits over 20 lines, Bash scripts over 25 lines |
| R2 | more than 25 Bash/Grep/Glob calls or 8 Reads per session (`ADCM_GUARD_BASH_CAP`, `ADCM_GUARD_READ_CAP`; environment caps can only lower the defaults) |

Escape phrases, accepted only from the owner's own prompt (not inside quotes, code or hand-backs): `sin tanto lío` (that turn) and `modo directo` (sticky until `modo orquestador`). Direct mode switches off R2, R3, R6, X1 and X2; T0, R1, R1b and M1 stay on.

An internal error never means allow: a parse-free fallback keeps the compaction lock, the handoff gate, the budget, the Bash size caps and a textual tamper check. Errors are visible as `⚠ guard errors: n` in the counter line and in `errors.log` (capped at 200 lines).
When a session's state is missing or unreadable, the guard rebuilds it from the session transcript (Bash and Read counts, compactions, handoff written) instead of starting at zero; a new session after `/clear` still starts at zero.

### Known limits

The guard stops drift and casual resets; it does not try to withstand a session that deliberately works around it.
Out of scope: paths assembled at run time (interpreter one-liners, shell variables), deliberately obscured working directories, and switching the plugin off in the settings file.
Deleting the guard's state does not reset the counters.

The guard is a hard stop against drift, not a sandbox. The tamper rule and the heavy-read rule parse shell text, so they cannot see a path built at run time:
interpreter one-liners, shell variables, shells nested more than one level, and writes made by tar, curl or awk.
The Bash / Read budget and the compaction breaker do not depend on that parsing and remain the backstop.
Disabling the plugin in the settings file is outside the guard's reach. `/clear` starts a new session with fresh counters by design.
Heredoc bodies are scanned as if they were commands, so a body that names the guard's paths is denied: write such files with the editor tools.
Very large or slow-to-parse commands (over 16 KB, or over 0.6 s of evaluation) are judged by the coarse rules without word-by-word parsing; on the attended main thread outside direct mode a command over 16 KB is denied (edit cap).
Without the `fcntl` module, parallel calls can lose counts.

## Selftests and launchers

`python3 scripts/selftest-all.py` discovers and runs every `*-selftest.py` (one line per suite, a total, exit 1 on any failure); flags `--only SUBSTR`, `--list`, `--mutation` (kills one key condition per suite and requires the suite to fail). Launchers are described in `scripts/launchers/README.md`.

## Project container convention

The generators share one filesystem convention (canonical spec:
`skills/execution-prompt-architect/references/project-structure.md`). A container
lives in one of **two homes**, by relationship: `~/<venture>/` for own ventures
(e.g. `~/<venture>/`), or `~/clientes_projects/<client>/` for client work. It
is **never a git repo** — `<container>/{ai, projects}` — EVERYTHING AI lives under
`ai/`: `ai/<slug>-{ai|ia}-{admin|common}/` (plus per-venture variants `-commercial`,
`-platform`, `-academic`) holds the plugin marketplaces, one git repo each; and the
code lives under `projects/` (or `p-engineering/`/`engineering/`) — a plain grouping
folder with **one git repo per engineering project**.

The execution brain, `ai-brain/`, has **three supported positions**: canonical
`ai/ai-brain/` (its own git repo holding ALL documentation — execution docs, the
product's spec/plan/decisions/backlog under `docs/`, and lazy per-module doc under
`modules/<mod>/`); the container root, `<container>/ai-brain/`; or `docs/ai-brain/`
with a symlink `ai/ai-brain -> ../docs/ai-brain` that is MANDATORY in that third
case — the `artifact-guard` Stop hook only discovers `ai/ai-brain/artifacts.json` or
`ai-brain/artifacts.json`, so any other layout silently disables it. Each engineering
project carries a gitignored `ai-brain` symlink (to wherever the brain actually lives,
or its `modules/<mod>`) so relative doc paths resolve in build sessions. The container
layout is documented in `ai/ai-brain/README.md`, never in loose root files — including
which document-name set (English or Spanish) the container uses (rule 9).
