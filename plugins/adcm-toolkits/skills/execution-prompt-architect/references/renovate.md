# Renovate an existing brain

Read when the user says 'renovate the brain', 'upgrade the brain', 'renueva el brain' or
'actualiza el protocolo'. It brings an older brain up to the checker's target
(`renovate_check.py --version`) and never re-plans: wave scope, state and logbook history stay.

## 0. Requirement and snapshot
Deterministic first, model second. `{{skill_dir}}` = this skill's base dir; `<docs_dir>` = the brain.
- A plugin version that ships `renovate_check.py` is loaded (`/reload-plugins` or a new session).
- Never read `task.md` or `execute.md`. State first:
  `python3 {{skill_dir}}/templates/status_digest.py --brain <docs_dir>`
- Then the snapshot (keep the output, it goes into every brief):
  `python3 {{skill_dir}}/templates/renovate_check.py --brain <docs_dir> --all-modules --invariants`
  Exit 0 `up-to-date` (stop: 0 agents) · 1 `needed(<blocks>)` · 2 no brain or unreadable · 64 usage.

## 1. Scripts (deterministic, 0 agents)
`renovate_check.py --brain <docs_dir> --all-modules --copy-scripts` copies the missing SCRIPTS files
into `<docs_dir>/scripts/` and nothing else. A differing copy is informational (`SCRIPTS ok · custom:
<file>`) and never blocks `up-to-date`: keep it when customised (own builders, titles), else `--force-outdated`.

## 2. One executor per needed block
For EVERY block listed in `needed(...)` (state `missing`, `partial`, `unparsed`; RULES: `needed`), ONE
`Agent(subagent_type: "adcm-toolkits:executor")` (sonnet) with
`{{skill_dir}}/templates/renovate-brief.md`, the check output and the snapshot pasted in.
- Order, sequential: ARTIFACTS → EXECUTE → TASK → RULES. Modules after the root brain.
- RULES (`needed` when it has `fix` findings): the checker resolves its targets itself — the project memory dir
  from `$CLAUDE_CONFIG_DIR` + the container path, the container `CLAUDE.md`/`AGENTS.md`, the
  brain `README.md` (`--memory-dir PATH` overrides, `--no-rules` skips). `fix` findings → ONE
  executor with the RULES block; `review` findings are never touched, they go to the owner in
  the final message. The memory lives outside the repo and is never committed.
- CONTEXT runs last and only when the check says `CONTEXT ok (<skill>)` (the executor
  runs that skill's STEP 4.5 `--update`); `n/a` is skipped.
- A block that returns `STOP` (an invariant would change, or it needs re-planning) goes to the user.

## 3. Audit gate
ONE `Agent(subagent_type: "adcm-toolkits:auditor")` (read-only), brief ≤40 lines:
- `git -C <docs_dir> diff --stat`: only the expected files, no deletions of history;
- the INVARIANTS line (s7 headers, h2 sections, logbook entries, wave rows) before and after:
  identical; `lines=` is informational and may grow;
- `renovate_check.py --brain <docs_dir> --all-modules` → `RENOVATE: up-to-date`;
- a public brain additionally gets the privacy grep over the added lines.
Findings go back to the SAME executor (`SendMessage`, cost 0).

## 4. Close
- Doc-sync in the brain's own repo: the logbook entry `[REFRESH] protocol <target>` (with its
  `Next:` line) appended as the ≤20-line orchestrator shortcut (logged), then commit + push.
- ONE `Agent(subagent_type: "adcm-toolkits:courier")` with the `artifact-courier` skill's
  `templates/courier-brief.md`, `REGEN: yes` (pages regenerated by the new `regen`); its links
  block goes last in the final message, nothing after it.

## 5. Idempotency and budget
Repeating the phrase on a renovated brain prints `RENOVATE: up-to-date`, 0 agents. Typical budget
3-5 of the 20: executors 2-4, auditor 1 (1 Opus quota; `model: sonnet` once spent), courier 1.

## Sessions without the agent types
No `adcm-toolkits:*` types in the session (not reloaded): `Agent(subagent_type: "general-purpose",
model: "sonnet")` with the same briefs, one per block. Say it plainly: "Renovate this brain to the
current protocol: apply each block the check lists from `renovate-brief.md`, one sonnet agent per block."
Two states have no executor route and go back to the owner: `needed(scripts)` after a failed copy (`failed x (symlink)`, read-only dir) and `ARTIFACTS unparsed` (a registry `--set-regen` cannot repair).
